# 第 8 週今日 Python 練習題：多頁爬蟲與 CSV 資料儲存

## 題目說明

在實際的爬蟲任務中，目標網站的資料通常分散在多個頁面（分頁）中。本題將練習如何自動翻頁爬取所有資料，並將結果整理後儲存成 CSV 檔，方便後續分析。

我們以模擬一個書單網站為例：假設該網站每頁顯示 5 本書，共有 3 頁，每本書有書名、作者、價格三個欄位。

## 技術要求

- 概念：迴圈控制、多頁爬取邏輯、URL 參數組合、CSV 寫入
- 需要的模組：`requests`、`beautifulsoup4`、`csv`、`time`

## 具體任務

1. **建立模擬資料函式**
   建立一個函式 `fake_page_html(page)` 回傳模擬的 HTML 字串，其中包含 5 本書的 `<div class="book">` 元素，每本書有 `<h3 class="title">`、`<span class="author">`、`<span class="price">` 三個子元素。書名可用「書名A-頁碼-編號」格式。

2. **撰寫解析函式**
   建立 `parse_books(html)` 函式，使用 BeautifulSoup 解析 HTML，回傳一個 list，每個元素是包含 `title`、`author`、`price` 的 dict。

3. **實作多頁爬取**
   建立 `scrape_all_pages(total_pages)` 函式：
   - 用迴圈從第 1 頁爬到最後一頁
   - 每頁爬取後等待 1 秒（`time.sleep(1)`）模擬禮貌爬取
   - 累積所有頁面的書本資料到一個 list 中
   - 印出目前進度，例如「正在爬取第 2/3 頁...」

4. **儲存成 CSV**
   建立 `save_to_csv(books, filename)` 函式：
   - 使用 `csv.DictWriter` 將資料寫入檔案
   - 欄位順序：`title`、`author`、`price`
   - 寫入前先寫入標頭列（`writeheader()`）

5. **主程式整合**
   在 `if __name__ == "__main__":` 中呼叫上述函式，爬取 3 頁，儲存為 `books.csv`，最後印出「共儲存 X 筆資料」。

## 範例

```python
# 預期執行輸出：
正在爬取第 1/3 頁...
正在爬取第 2/3 頁...
正在爬取第 3/3 頁...
共儲存 15 筆資料至 books.csv

# books.csv 前幾行：
title,author,price
書名A-1-1,作者1-1,NT$150
書名A-1-2,作者1-2,NT$200
...
```

## 提示

- 組合 URL 時可用 f-string：`url = f"https://example.com/books?page={page}"`
- `csv.DictWriter` 的 `fieldnames` 參數要與 dict 的 key 一致
- 記得在開啟 CSV 時加上 `encoding='utf-8-sig'`，讓 Excel 正常顯示中文
- 若要判斷「是否還有下一頁」，可檢查該頁回傳的書本數量是否為 0

## 學習重點

**與爬蟲的關聯：**
- 真實網站常見的翻頁方式有兩種：URL 參數換頁（`?page=2`）和「下一頁」按鈕（需判斷按鈕是否存在）
- `time.sleep()` 是基本爬蟲禮儀，避免對伺服器造成過大壓力
- CSV 是爬蟲資料最常見的儲存格式，可直接用 pandas 讀取分析

**與資料分析的關聯：**
- 下週的 NumPy、Pandas 課程中，你會學到如何用 `pd.read_csv()` 讀取今天產出的 CSV 進行統計與篩選

## 進階挑戰（選做）

1. **動態偵測頁數**：不要寫死 `total_pages=3`，改為爬取第一頁時從 HTML 中讀取總頁數（假設有 `<span class="total-pages">3</span>`）。

2. **斷點續傳**：若程式中途中斷，重新執行時從上次失敗的頁面繼續，而非從頭開始（提示：記錄已爬完的頁碼到一個狀態檔）。

3. **加入錯誤處理**：若某頁請求失敗（模擬 `raise requests.exceptions.Timeout()`），自動重試最多 3 次，超過則跳過該頁並記錄 warning。
